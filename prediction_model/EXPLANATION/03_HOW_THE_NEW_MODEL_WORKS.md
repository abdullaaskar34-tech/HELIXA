# How the new model works

## The idea in one paragraph

The old model was fitted to hard labels and then reported how sure it was about
reproducing them — which, because those labels are the clustering's own output,
is a circular question it could answer with near-certainty. The new model is
fitted to the **consensus profile** instead: for each patient, the fraction of
1,000 resampled clusterings in which that patient co-clustered with each of the
six subtypes. Those numbers measure something real and non-circular, and by
training against them directly the model's output probabilities *become*
consensus memberships rather than having to be softened into looking like them.

## Getting the target

The consensus matrix was never saved — only the derived `consensus_own` and
`consensus_best_other` columns survived. It was regenerated by re-running the
Monti procedure with the original seed, and it reproduced exactly (ARI
1.000000, membership values matching the recorded file to 0.0000; details in
`02_THE_PREPROCESSING_CONTRACT.md`).

From the recovered 328×328 matrix, the full profile for patient *i* and cluster
*c* is the mean consensus between *i* and the members of *c*:

```
prof[i, c] = mean( C[i, j] : j in cluster c, j != i )
q[i, :]    = prof[i, :] / sum(prof[i, :])
```

`q` is a proper distribution over the six subtypes. Row sums before
normalisation are 1.014 on average (range 0.875–1.104), so the normalisation is
a light touch — `q[i, own]` correlates **0.9646** with the recorded
`consensus_own`, and no CORE patient ends up below 0.5.

This is a genuinely richer target than what was available before. The recorded
file only gave the own-cluster value and the best competing one; the profile
gives all six, so the model learns the shape of the ambiguity — *which* other
subtype a borderline tumour is drifting towards, not just that it is drifting.

## Fitting

Soft-target cross-entropy,

```
loss = - sum_i sum_c  q[i,c] · log p_c(x_i)
```

is implemented by replicating each patient once per class and weighting each
copy by that class's consensus share. That is exactly what scikit-learn
optimises under `sample_weight`, so no custom solver is needed:

```python
Xr = np.repeat(E, 6, axis=0)
yr = np.tile(np.arange(6), 328)
wr = q.flatten()
LogisticRegression(max_iter=20000, C=C).fit(Xr, yr, sample_weight=wr)
```

Three deliberate differences from v1:

1. **All 328 patients**, not 273. The 55 BOUNDARY tumours are the ones that
   teach the model what uncertainty looks like. Excluding them was the original
   mistake.
2. **C chosen by cross-validated cross-entropy against the soft target**, not
   by accuracy. Selected `C = 0.316`. The objective is flat above ~0.3, so the
   exact value is not load-bearing.
3. **No post-hoc calibration step.** An earlier iteration fitted a temperature
   on top of a hard-label model, which worked (median confidence fell from
   0.9993 to 0.7370) but could only rescale confidence, never reorder it. Soft
   targets make the rescaling unnecessary because the model is optimising the
   right thing from the start.

## Why a plain linear model

Twelve model families were compared, all scored out-of-fold against the
consensus profile:

| model | profile RMSE | corr (all cells) | argmax acc |
|---|---|---|---|
| **LogReg 5PC, C=3.2** | **0.0763** | **0.9659** | 0.9787 |
| LogReg 5PC, C=0.32 | 0.0766 | 0.9656 | 0.9787 |
| LogReg poly-2, C=10 | 0.0819 | 0.9601 | 0.9512 |
| LogReg poly-3, C=1 | 0.0831 | 0.9595 | 0.9543 |
| LogReg poly-2, C=1 | 0.0878 | 0.9547 | 0.9512 |
| ExtraTrees 500 | 0.0889 | 0.9594 | 0.9451 |
| kNN k=10, distance | 0.0954 | 0.9496 | 0.9085 |
| RandomForest 500 | 0.1050 | 0.9349 | 0.8811 |
| kNN k=20, distance | 0.1108 | 0.9364 | 0.9116 |
| kNN k=30, distance | 0.1217 | 0.9281 | 0.9116 |
| kNN k=25, uniform | 0.1244 | 0.9218 | 0.8963 |
| kNN k=40, distance | 0.1334 | 0.9170 | 0.8933 |

Every more flexible alternative is **worse**. Polynomial expansions, tree
ensembles and nearest-neighbour regression all lose to the plain linear fit.

That is an informative negative result. It means the residual scatter is not
the model underfitting — it is variation in the consensus profile that the 5
principal components simply do not determine. Adding capacity fits noise. The
linear model is the right one, and its error is close to irreducible given
these features.

## What comes out

For every sample, the predictor returns:

- **cluster** and subtype label
- **probability** for each of the six subtypes (summing to 1)
- **margin** to the runner-up, and a **CORE / BOUNDARY call** using the same
  τ = 0.50 threshold the clustering used for its own core/boundary split
- **`library_batch`** — the detected protocol, plus the non-polyA fraction and
  the threshold it was compared against
- **Verhaak signature scores** (Proneural, Classical, Mesenchymal, Neural) and
  **`verhaak_nearest`**
- **seven pathway scores** (MTC/OXPHOS, GPM glycolysis-lipid, PPR
  proliferation, NEU neuronal, oligodendrocyte-myelin, immune-myeloid,
  hypoxia-angiogenesis)
- the 5-D embedding coordinates and gene-coverage diagnostics
- if the sample is one of the 328, its **recorded** assignment alongside the
  model's independent read

The signature and pathway scores are plain means of z over their gene sets. They
never touch the classifier, so they are an independent check on the call.
